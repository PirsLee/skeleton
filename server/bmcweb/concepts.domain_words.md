
[1] C++中的对象

一块存储区域+类型+生命周期。

[2] C++中的类

类本身不是对象，类定义也不等于创建对象，在C++里，类是类型，对象是该类型的实例，是一块有类型和生命周期的存储区域。

[3] 类型的语义

特指class

> 朴素模型：一个类型规定了一组值（值域）、这些值上允许的操作、值的表示方式，以及程序必须遵守的规则。

|视角|类型语义|回答的问题|
|---|---|---|
|指称语义|类型指称一个数学对象（集合/域），表达式指称值|这个类型代表什么值|
|操作语义|类型决定程序如何一步步执行、值如何被构造消费|运行时会怎么样|
|公理语义|类型由不变量、前置/后置条件、代数定律刻画|能保证什么性质|
|代数语义|类型=载体+操作+满足的等式/定律|操作之间有什么关系|
|表示语义|类型规定底层存储布局和编码|内存里长什么样|

[4] 业务语义与类型语义的转换

**怎么从软件中或者类型中恢复出业务语义？**

1. 从类型形态识别业务角色

|类型形态信号|业务角色候选|
|---|---|
|只有数据成员+比较/哈希，无行为|值对象、DTO、配置项、标识符|
|强类型包装单个字段|领域值概念，防单位混用|
|enum class + 有限取值|业务枚举、状态、类别、模式|
|抽象基类+纯虚函数|业务接口/端口、扩展点、策略|
|类 + unique_ptr成员 + 析构释放|资源拥有者，生命周期实体|
|类 + shared_ptr成员|共享资源、缓存、注册表条目|
|类 + std::span/string_view成员|非拥有视图，生命周期依赖外部|
|模板参数化策略|可配置业务规则、格式/协议族|
|std::variant成员|业务状态机、多态数据|
|大量static方法、无状态|工具/服务函数、纯计算|
|单例/全局访问点|全局服务、注册表、配置中心|
|类 + 锁/原子成员|并发共享状态、线程安全实体|
|类 + 回调/观察者注册|事件源、发布者、扩展挂载点|

2. 从命名恢复业务概念

命名不可靠，需要和其他交叉验证

类型名 --> 领域值概念

成员名 --> 实体属性

函数名 --> 生命周期状态机start、stop、open、close等/业务操作，与业务有关的操作

命名空间/目录 --> 业务分层/适配层

后缀约定：\*View非拥有、\*Handle句柄、\*Config配置、Manager协调者、Factory创建

动词模式：validate*、normalize*、convert* --> 业务规则/转换


3. 从构造函数/不变量/断言恢复业务规则

- 构造函数产生业务

- const成员函数：承诺不可修改可观察状态，该状态是值而非可变实体

4. 从所有权/生命周期恢复资源语义

- unique_ptr：独占所有权，业务上“谁创建谁负责”

- shared_ptr：共享生命周期，业务上“多方持有、最后释放”

- weak_ptr：观察但是不延长生命周期，业务上“缓存/回引用”

- 裸指针/引用成员：非拥有观察者，业务上“借用”，生命周期由外部保证

- std::span/string_view：非拥有视图，业务上“临时借用一段数据”

- RAII包装：资源获取即初始化，业务上“作用域即资源生命周期”

- 移动语义：业务上“资源不可复制，只能转移”

5. 从调用图/数据流恢复业务流程

- 调用链：业务生命周期流程

- 数据流：业务处理管线

- 虚调用候选集：业务扩展点/平台适配

- 回调注册点：事件/扩展机制

- 异常路径：业务失败处理边界

- 锁边界：业务共享状态与并发契约

6. 从模块边界恢复业务边界

模块恢复的是业务子域和它们的依赖关系，而不是代码目录本身

- 目录/命名空间/构建target：业务子域划分

- 依赖方向：分层/依赖规则

- 公共头文件：业务对外契约

- 循环依赖/跨层调用：业务边界泄漏或历史遗留

- 第三方库边界：适配层/防腐层

7. 从设计模式恢复设计意图

模式一般对应了设计意图和设计决策。
