# sensor.hpp

class Sensor

所有sensor的基类。它定义了“一个sensor长什么样子”

继承：
    
    无，只有本身的能力。

数据成员：

    _name 传感器名称
    _timeout 传感器数据的新鲜度超时
        如果距离该传感器最后一次成功更新数据的时间，超过了timeout秒，就认为这个传感器已经失效，系统必须进入安全模式。
        相当于看门狗概念，timeout是传感器数据有效期的看门狗。

函数成员：

    获取数据成员的getter方法。
    需要子类实现的：
        读取传感器的方法read
        写入传感器的方法write

        析构方法~Sensor，也就是生命周期结束的方法。

职责：

    为具体的传感器提供定义。

    read ： 读传感器
    write ： 写传感器
    ~Sensor ： 析构传感器类的生命周期
    GetTimeout / GetName ：对外提供获取对象状态的方法

# manager.hpp

SensorManager只是一个注册表+总线管理器：它负责“有哪些传感器，按什么名字找，按什么类型分组，用哪条D-Bus总线”这件事情。

真正的怎么读温度、怎么读转速、怎么处理硬件错误，是Sensor的派生类干的事情。

```
┌────────────────────────────┐
                    │  SensorManager              │
                    │                            │
                    │  _sensorMap:               │
                    │  "cpu0_temp" → Sensor◎     │
                    │  "fan0_tach" → Sensor◎    │
                    │  "gpu0_margin" → Sensor◎  │
                    │                            │
                    │  _sensorTypeList:          │
                    │  "temp" → [cpu0_temp, gpu0_margin]  │
                    │  "fan"  → [fan0_tach, fan1_tach]    │
                    └────────────────────────────┘
```

职责：

    addSensor   注册一个传感器，按名字存map，按类型加索引
    getSensor   根据名字找到对应的Sensor对象
    getPassiveBus / getHostBus  对外提供两条DBus总线句柄
    构造函数    初始化两条总线，并在host bus上创建/xyz/openbmc_project/extsensors的DBus对象管理器
